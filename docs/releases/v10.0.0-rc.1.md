# v10.0.0-rc.1

Release candidate: 2026-10-15

## English

### Fork version line

- This fork now has its own version line, starting at 10.0.0 so it can never collide with upstream 8.x/9.x. `VERSION`, the Rust workspace and `ccb-kernel` all report `10.0.0-rc.1`; `ccb --version` prints `ccb-native 10.0.0-rc.1 (core 10.0.0-rc.1)`.
- Scope: the native Rust runtime on Windows 11 + pwsh + Herdr, with Pi, Codex and Claude. The legacy Python launcher (`ccb.py`) and the upstream npm/desktop/mobile metadata keep their upstream versions and are not part of this release.

### Cancellation

- `ccb cancel` now works for Pi and Claude running as Herdr terminal agents. Before, it failed with "native cancellation control is not yet implemented". CCB sends Esc once, and the provider's own history decides the outcome. A turn that finished before the Esc still completes. A task whose prompt was never sent is cancelled immediately, without any input to the terminal.
- Pressing Esc yourself in a Claude pane no longer faults the agent. The interrupted turn is recorded as `cancelled` (`claude_turn_interrupted`).

### Recovery

- A Pi or Claude terminal provider that dies mid-turn no longer leaves its agent permanently stuck. `ccb kill` followed by `ccb herdr open` settles the unfinished task from provider history as `incomplete`, never resends it, clears the fault and resumes the original session.
- An agent held for missing session evidence can now be recovered again. Restored evidence resumes the exact original session.
- New offline command `ccb herdr repair <agent> --fresh-session [--dry-run]`: an explicit operator decision to give up an unverifiable session. Sent work closes as `incomplete` without replay, and the agent starts a fresh session. See `docs/native-held-agent-repair.md`.
- A verified session binding is no longer discarded when a provider dies, and recovery after `ccb kill` works when an agent was held in the previous generation.

### Status reporting

- `ccb agents`, health views and `ccb herdr open` report `provider_fault` for any agent with a blocked fault. Native Codex hosts report `native_host_session_verified` or `awaiting_native_host_session`. A display that has disappeared is shown as `lost`, never as ready.

### Context controls and skills

- `ccb clear` and `ccb compact` now work for Pi and Claude running as Herdr terminal agents. Before, they were refused as `native_context_protocol_unsupported`. CCB types the provider's own `/compact`, `/clear`, or Pi's `/new` exactly once. A clear completes when the new session is observed and is recorded as a session rotation, so later tasks, reopen and recovery use the new session. See `docs/native-context-controls.md`.
- A Pi session started by `/new` that never received a task no longer blocks recovery.
- New `ccb skills status|install`: installs the `ask`, `ccb-clear` and `ccb-compact` control skills for Pi, Claude and Codex. Pi had none before. Skills you edited, or installed by other means, are left alone unless you pass `--replace-unmanaged`.
- Closing one agent's Herdr pane no longer breaks the others. That agent is reported as lost; its peers keep returning results, and `ccb herdr open` and `ccb kill` still work.

### Verification and upgrade notes

- Verified with real Pi, Codex and Claude accounts in a real repository:
  - delegation;
  - cancelling running tasks;
  - killing each provider mid-turn;
  - stopping the daemon mid-turn.

  None replayed a task, sessions were resumed, and the repository stayed unmodified. Approval prompts were not exercised, because that machine's Codex configuration never asks.
- Full native suite: 1399 passed. Every remaining failure is pre-existing and none was introduced by this release:
  - non-scope providers;
  - installation tests, which time out only on debug builds (all 61 pass on release builds);
  - random Keeper-timing cases in `test_native_worktree_lifecycle`.
- Upgrade: from outside the stopped prefix, run `ccb-native installation upgrade --prefix <dir> --dry-run`, then run it again without `--dry-run`. The previous program directory is kept for rollback. Restart a running project's daemon with `ccb stop` followed by `ccb herdr open`. No conversation migration is required.
- Known limitations:
  - Launch `ccb herdr open` from pwsh. A git-bash launch gives pane shells the wrong working directory.
  - Reopen from the same shell environment you first launched from. The launch plan includes an environment hash.
  - Adding or removing agents in an existing Herdr project still needs a migration that is not implemented.
  - `ask` reads stdin until EOF whenever stdin is not a terminal.
  - The first Claude workspace-trust prompt can make the first open time out. Open again after confirming it.

## 中文

### Fork 版本线

- 本 fork 启用独立版本线，从 10.0.0 开始，不会与上游 8.x/9.x 撞号。`VERSION`、Rust workspace 和 `ccb-kernel` 统一为 `10.0.0-rc.1`；`ccb --version` 显示 `ccb-native 10.0.0-rc.1 (core 10.0.0-rc.1)`。
- 范围：Windows 11 + pwsh + Herdr 上的原生 Rust 运行时，provider 为 Pi、Codex、Claude。旧的 Python 启动器（`ccb.py`）和上游的 npm/桌面/手机端元数据保留上游版本号，不属于本次发布。

### 取消

- 以 Herdr 终端模式运行的 Pi 和 Claude 现在可以用 `ccb cancel` 取消。之前会直接报错 "native cancellation control is not yet implemented"。CCB 只发送一次 Esc，结果以 provider 自己的历史记录为准；Esc 之前已经完成的轮次仍然算完成；prompt 尚未发出的任务会立即取消，不向终端发送任何输入。
- 用户自己在 Claude 面板里按 Esc，不会再让 agent 进入 fault；被打断的轮次记录为 `cancelled`（`claude_turn_interrupted`）。

### 恢复

- Pi 或 Claude 终端 provider 在执行中途退出后，agent 不会再永久卡住。执行 `ccb kill` 后再 `ccb herdr open`，未完成的任务会按 provider 历史判定为 `incomplete`、绝不重发，fault 自动清除，并接回原会话。
- 因会话证据缺失而被 hold 的 agent 现在可以再次恢复；证据恢复后会接回原来的会话。
- 新增离线命令 `ccb herdr repair <agent> --fresh-session [--dry-run]`：由操作者明确决定放弃无法验证的会话，已发送的任务以 `incomplete` 结束、不重放，agent 以新会话启动。详见 `docs/native-held-agent-repair.md`。
- provider 退出时不再丢弃已验证的会话绑定；上一代中有 agent 被 hold 时，`ccb kill` 之后也能正常恢复。

### 状态显示

- 只要有阻塞 fault，`ccb agents`、健康视图和 `ccb herdr open` 都显示 `provider_fault`。托管 Codex 显示 `native_host_session_verified` 或 `awaiting_native_host_session`。已经消失的显示面板显示为 `lost`，不再误报可用。

### 上下文控制与 skill

- 以 Herdr 终端模式运行的 Pi 和 Claude 现在支持 `ccb clear` 和 `ccb compact`。之前会以 `native_context_protocol_unsupported` 被拒绝。CCB 会准确地输入一次 provider 自己的命令：`/compact`、`/clear`，或 Pi 的 `/new`。clear 在观察到新会话后才算完成，并记录为会话轮换，之后的任务、重新打开和恢复都会使用新会话。详见 `docs/native-context-controls.md`。
- Pi 通过 `/new` 开出的新会话如果从未接收任务，不再阻塞恢复。
- 新增 `ccb skills status|install`：为 Pi、Claude、Codex 安装 `ask`、`ccb-clear`、`ccb-compact` 控制 skill，Pi 之前完全没有这些 skill。你修改过的、或通过其他方式安装的 skill 默认不会被覆盖，除非加 `--replace-unmanaged`。
- 关掉某个 agent 的 Herdr 面板不再影响其他 agent：该 agent 显示为丢失，其他 agent 照常回传结果，`ccb herdr open` 和 `ccb kill` 仍可正常使用。

### 验证与升级说明

- 已在真实仓库中用真实的 Pi、Codex、Claude 账号验证：
  - 派活；
  - 取消运行中的任务；
  - 执行中途杀掉各 provider；
  - 执行中途停止 daemon。

  均未重放任务，会话都接回了，仓库没有被改动。审批流程未验证：该机器的 Codex 配置不会发起审批。
- native 全量测试 1399 个通过。剩余失败都是早已存在的，本版没有引入新失败：
  - 不在范围内的 provider；
  - 安装测试，只在 debug 构建上超时（release 构建上 61 个全部通过）；
  - `test_native_worktree_lifecycle` 中随机出现的 Keeper 时序用例。
- 升级：在已停止的安装目录外部执行 `ccb-native installation upgrade --prefix <目录> --dry-run`，确认后去掉 `--dry-run` 再执行一次。旧程序目录会保留用于回滚。正在运行的项目执行 `ccb stop` 后再 `ccb herdr open` 即可切换到新 daemon，无需迁移对话。
- 已知限制：
  - 请从 pwsh 执行 `ccb herdr open`：从 git-bash 启动时，面板 shell 的工作目录不正确。
  - 请从首次启动时相同的 shell 环境重新打开：启动计划包含环境哈希。
  - 已有 Herdr 项目增减 agent 仍需要尚未实现的迁移。
  - stdin 不是终端时，`ask` 会一直读到 EOF。
  - 首次信任 Claude 工作区时，第一次 open 可能超时；确认信任后再 open 一次即可。
