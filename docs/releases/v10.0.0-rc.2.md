# v10.0.0-rc.2

Status: unreleased (changes on `main` since v10.0.0-rc.1)

## English

### Delegation results reach their caller

- A Claude agent that `cd`s into a subdirectory of its workspace during a task
  no longer faults with "Claude transcript workspace changed". Directories
  inside the bound workspace are accepted; sibling and parent directories are
  still rejected.
- A Claude agent that submits `ask` as a background command no longer faults
  with `provider_protocol_error` when Claude Code resumes the turn with its
  background-task notification. The notification continues the same turn, and
  the answer given before it is kept in the reply instead of being replaced by
  the acknowledgement that follows. Before this fix the parent job never
  finished, so a `--chain` child's result stayed queued.
- A Claude agent whose context auto-compacts in the middle of a task no
  longer faults with `provider_protocol_error`. The compaction boundary and
  its summary continue the same turn; a summary of other turns still counts
  as a new request.

### Results delivered to Pi no longer merge with your draft

- CCB used to type a task or a returned result into Pi's editor. If you had
  an unsent draft there, the two were submitted as one message; CCB could not
  recognize the merged turn, so that delivery stayed open and every later
  result for Pi queued behind it.
- The Pi bridge now submits CCB's prompt itself with `pi.sendUserMessage`,
  outside the editor and only while Pi is idle. Your draft stays in the
  editor untouched. A Pi session started by an older bridge keeps the typed
  delivery until it is reopened with `ccb kill` and `ccb herdr open`.
- A request Pi has not taken yet is withdrawn when the worker stops or the
  daemon restarts, so it can never be delivered late. `ccb cancel` withdraws
  it too, before it reaches Pi. A task whose request was withdrawn by a
  restart ends as `incomplete` right away instead of faulting Pi an hour
  later, and a withdrawn result for Pi is requeued and delivered once.

### `ask` and stdin

- `ask` no longer blocks forever on a stdin that never closes, such as the pipe
  Claude Code's Bash tool gives its commands. Before, the delegation hung and
  the job was never submitted.
- Behavior change: a message given as arguments is now the whole message.
  stdin is read only when no message argument is given. Previously the two
  were joined. When arguments are given and stdin already holds data, `ask`
  prints `stdin ignored because the message was given as arguments` to stderr.
- A stdin that stays open without input for 60 seconds is refused with an
  error instead of blocking.

### Coordination rules

- Delegation requests now carry only the receiver's stage: task, inputs,
  constraints, expected reply. They no longer restate the user's whole goal
  and every remaining stage.
- For a user-ordered pipeline such as "A reviews, then B fixes", the lead asks
  A once; A passes the work to B with `ask --chain` and relays B's result
  unchanged. Every stage no longer returns to the lead first.
- Returned results are reported with their status and verification, and are
  re-run or re-dispatched only when asked. The rules injected with each task
  are shorter than before.

### Starting a project and Herdr names

- A bare `ccb` in a project whose configuration uses the Herdr backend (the
  default) now opens it, like `ccb herdr open`. Before, it started a headless
  daemon without panes. `ccb start` still starts the daemon on its own, and a
  bare `ccb` run inside a CCB agent keeps that behavior.
- Herdr's sidebar now shows readable names. Agent rows show the agent name
  (for example `pi_lead (pi)`) instead of the internal `ccb-<id>` name, which
  stays the identity CCB verifies. A new workspace is labelled
  `<project directory> (ccb-<id>)` instead of `ccb-native-<uuid>`. Existing
  workspaces keep their old label until the project is closed with `ccb kill`
  and opened again; no migration is needed.

### Upgrade notes

- Stop every project that uses the prefix, upgrade, then run
  `ccb skills install` to refresh the Pi `ask` skill.
- The interactive coordination text is injected when an agent starts. Run
  `ccb kill` and then `ccb herdr open` to apply it to running agents;
  conversations are resumed.

## 中文

### 派单结果能回到调用者

- Claude agent 在任务中 `cd` 进工作区的子目录后，不再报 "Claude transcript workspace changed"。工作区内的目录都会被接受，隔壁目录和上级目录仍然拒绝。
- Claude agent 用后台方式执行 `ask` 时，Claude Code 会在后台命令完成后插入一条通知并继续这一轮。以前 CCB 会因此判 `provider_protocol_error`，父任务永远结束不了，`--chain` 子任务的结果一直排队送不到。现在这条通知算作同一轮的延续；通知之前的回答会保留在回复里，不会被之后那句状态说明替换。
- Claude agent 在任务中途自动压缩上下文时，不再判 `provider_protocol_error`。压缩分界和压缩摘要算作同一轮的延续；如果摘要压缩的是别的轮次，仍然算作新请求。

### 交给 Pi 的结果不再和你的草稿拼在一起

- 以前 CCB 把任务或返回的结果打进 Pi 的输入框再提交。如果你在输入框里有没发出的草稿，两者会被当成一条消息提交；CCB 认不出拼接后的这一轮，这条投递就一直不结束，之后所有要交给 Pi 的结果都排在它后面。
- 现在由 Pi bridge 调用 `pi.sendUserMessage` 自己提交 CCB 的消息，不经过输入框，而且只在 Pi 空闲时提交。你的草稿原样留在输入框里。旧版 bridge 启动的 Pi 会话仍然使用打字方式，`ccb kill` 后再 `ccb herdr open` 即可切换。
- Pi 还没取走的请求，会在 worker 停止或 daemon 重启时撤回，不会在之后被补发；`ccb cancel` 也会在它送达 Pi 之前撤回。因重启被撤回的任务立即以 `incomplete` 结束，不会在 1 小时后把 Pi 判为故障；被撤回的结果投递会放回队列，只重新送达一次。

### `ask` 与 stdin

- `ask` 遇到永远不关闭的 stdin（比如 Claude Code 的 Bash 工具给的管道）时不再无限卡住。以前派单会挂住，任务根本没提交。
- 行为变化：命令行参数里给了消息，参数就是完整的消息，只有没给消息参数时才读 stdin。以前两者会拼在一起。给了参数、而 stdin 里又已有数据时，`ask` 会在 stderr 提示 `stdin ignored because the message was given as arguments`。
- stdin 保持打开但 60 秒没有输入时，直接报错，不再无限等待。

### 协作规则

- 派单只写接收方这一步需要的东西：任务、输入、约束、要交回什么。不再重复用户的完整目标和全部后续阶段。
- 用户指定了 "A 审核后交给 B 修复" 这样的流水线时，Pi 只派一次给 A；A 用 `ask --chain` 交给 B，B 的结果回来后原样转交，不再每一步都先回到 Pi。
- 收到结果后，汇报时带上状态和验证记录；只有被要求时才重跑或再派一轮。每个任务附带的规则比以前更短。

### 项目启动与 Herdr 显示名

- 项目配置使用 Herdr 后端（默认就是）时，不带参数的 `ccb` 现在等同于 `ccb herdr open`。以前它只会在后台启动一个没有面板的 daemon。`ccb start` 仍然只启动 daemon；在 CCB agent 内部执行不带参数的 `ccb` 时，行为也保持不变。
- Herdr 侧边栏现在显示可读的名字：agent 行显示 agent 名（例如 `pi_lead (pi)`），不再显示内部的 `ccb-<id>`，CCB 仍然用内部名字校验身份；新建的工作区命名为 `<项目目录名> (ccb-<id>)`，不再是 `ccb-native-<uuid>`。已有的工作区保留旧名字，等项目 `ccb kill` 后重新打开时才会换成新名字，不需要迁移。

### 升级说明

- 先停掉所有使用该安装目录的项目，升级后执行 `ccb skills install` 更新 Pi 的 `ask` skill。
- 交互协作规则是在 agent 启动时注入的。要让正在运行的 agent 用上新规则，先执行 `ccb kill`，再执行 `ccb herdr open`；会话会接回。
